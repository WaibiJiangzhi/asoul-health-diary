# 一个魂生活日记设计系统

项目的公共视觉入口是 `css/design-system.css`。它只管理设计变量和基础控件，不负责某个页面的具体排版。

## 样式职责

| 要修改的内容 | 文件 |
| --- | --- |
| 全站颜色、字号、间距、圆角、阴影 | `css/design-system.css` |
| 首页构图和冷笑话卡片 | `css/pages/home.css` |
| 目标页、倒计时与进度目标 | `css/pages/goals.css` |
| 日程页、空间切换、周计划与日卡 | `css/pages/schedule.css` |
| 曲线页、图表、节点详情与相关弹窗 | `css/pages/charts.css` |
| 个人页、偏好设置、本地数据保险箱与头像弹窗 | `css/pages/personal.css` |
| 迁移期共享基础组件 | `css/legacy/styles.css` |
| 手机应用壳与跨页手机组件 | `css/platform/mobile-app.css` |
| 跨页平台适配规则 | `css/platform/responsive-platform.css` |

五个主页面现在都拥有唯一的页面样式入口。后续修改页面布局时，应直接进入对应页面文件，不再向旧修饰层追加覆盖。

## 视觉理念

这套界面采用“清爽的编辑式生活日记”方向：纸张负责留白和承载，应援色负责情绪与身份，角色素材负责温度，界面结构负责秩序。视觉调整不是不断叠加装饰，而是先保证内容关系、阅读顺序和操作反馈，再用少量有意义的细节建立记忆点。

- 保留横线纸、装订孔和三位成员的角色贴纸；它们是产品叙事的一部分。
- 嘉然、贝拉、乃琳的官方应援色是品牌色源，不以相近的通用粉、红、紫替代。
- 应援色可以生成浅底色和深文字色，但大面积正文、边框和背景仍以纸白、墨色和中性色为主。
- 不使用没有信息意义的大面积光晕、彩条、胶带、彩虹渐变和重复徽章。
- 状态色只表达状态，曲线色只区分数据；不能为了“更丰富”同时争夺注意力。
- 角色贴纸、台词和小图标按一个组合整体对齐，并在每个断点拥有明确安全区域，不能靠偶然的绝对定位避让。

## 页面阅读层级

每个页面遵循同一条阅读路径：页面眉题 → 主标题 → 主要操作 → 核心内容 → 补充信息。页面主标题在桌面保持约 `32px–49px` 的清晰层级，在手机保持约 `26px–34px`；正文原则上不低于 `13px`，只有坐标轴、胶囊标签和不承担主要信息的微型说明可以更小。

卡片内部先处理图文基线、上下节奏和可点击区域，再考虑阴影或色彩。空状态必须说明“现在是什么状态”和“下一步能做什么”，不留下形似故障的大片空白。

## 统一断点与阅读画布

- 紧凑应用视图：小于 `900px`
- 桌面网页视图：大于等于 `900px`
- 宽屏：大于等于 `1440px`
- 超宽屏：大于等于 `1920px`

页面结构只在 `900px` 发生手机/网页模式切换。组件确实需要控制信息密度时可以在主模式内增加一档，但不能借此建立第三套页面结构；例如表情选择器在 `600px–899px` 使用四列，在 `599px` 以下使用三列，滚动区域使用由内容撑开的固定轨道，格子始终保持正方形和完整图片，不能为了塞进弹窗高度而压缩网格行。CSS 自定义变量不能直接用于媒体查询，因此断点数值写在样式文件的 `@media` 中，不得继续增加相近且语义重复的断点。阅读画布由 `css/platform/responsive-platform.css` 统一管理：紧凑视图恢复为全宽，由页面卡片保留安全边距；普通桌面最大约 `1180px`、宽屏约 `1320px`、超宽屏约 `1600px`。大屏适配通过画布、字号令牌和组件尺寸共同完成，不使用 `zoom` 或整体缩放页面。

## 主要设计变量

### A-SOUL 色彩

- `--member-diana`：嘉然 `#E799B0`
- `--member-bella`：贝拉 `#DB7D74`
- `--member-eileen`：乃琳 `#576690`

倒计时、进度目标和空间卡共享同一套可选主题色。用户没有指定颜色时，界面按卡片顺序从乃琳深岩暗蓝灰、嘉然贝壳粉、薄荷绿、贝拉番茄红中自动轮换；一旦指定颜色，该颜色必须同时进入页面卡片、周报预览和周报下载图。颜色只承担识别与关联作用，不改变完成状态、数据含义或排序。

连续操作可以用三种应援色建立步骤识别，但必须有固定语义而不是重复装饰。AI 周计划导入中，嘉然贝壳粉表示“已有内容”，贝拉番茄红表示“新格式”，乃琳深岩暗蓝灰表示“最终导入”；按钮、编号、边框和浅背景都从同一个步骤变量派生。

### 字体

- `--font-sans`：全站正文
- `--text-xs` 至 `--text-xl`：正文层级
- `--title-sm`、`--title-md`：标题层级

### 间距

使用 `--space-1`、`--space-2`、`--space-3`、`--space-4`、`--space-5`、`--space-6`、`--space-8`、`--space-10`、`--space-12`。

### 圆角与阴影

- `--radius-xs` 至 `--radius-xl`：卡片和控件圆角
- `--radius-pill`：胶囊形状
- `--shadow-soft`、`--shadow-card`、`--shadow-raised`：三层阴影

## 修改规则

1. 调整全站公共视觉时，优先修改 `css/design-system.css` 的变量。
2. 调整单个页面布局时，只修改该页面自己的样式文件。
3. 页面可以引用公共变量，但不要重新定义同名公共变量。
4. 不用 `!important` 解决普通层叠问题；先确认选择器是否放错文件。
5. 新增一种尺寸前，先判断 `900px` 主模式断点和现有组件密度档能否解决。
6. 每次迁移一个页面，确认手机和桌面视觉后再删除旧规则。
7. 新增装饰前必须说明它承担的叙事或信息作用；纯填空装饰不进入公共组件。
8. 新功能优先复用现有卡片、按钮、表单和空状态层级，确实出现新语义时再扩展令牌。
9. 同一项用户数据出现在页面、弹窗和导出图时，其主题色必须来自同一个数据字段；不得在各处复制独立的颜色判断。
10. 同一操作组中的按钮由父级组件统一尺寸、字号、字重、圆角和内边距；主按钮、次按钮和危险按钮只改变语义色与强调等级，不能各自漂移。
11. 目标、进度、空间和曲线标题旁的“新建”统一使用 `.section-add-button`；手机显示无底色加号，桌面显示“＋ 新建”，页面不得再为同一按钮增加圆形背景或专属几何。
12. 日程月份工具栏在宽桌面保持说明在左、筛选和操作在右，空间不足时才换成上下两行；当天切换属于日卡头部，宽桌面紧跟可编辑的当天标题并与操作区左对齐，标题保留悬停和聚焦下划线，并在状态区下方用一行说明文字提示可以修改；日卡表情在头部整体高度内居中，不能以负边距悬浮在卡片边缘。
13. 空间表情、目标表情和日卡表情的尺寸必须随卡片一起分档；不能只拉伸图片，也不能在大屏卡片中继续使用手机级小图案。承载白底表情的圆角框使用白色画布，主题色只进入边框或交互状态，避免图片边缘出现色块。
14. 曲线主线保持轻而清楚的约 `2.5px–2.7px` 视觉线宽，导出图按画布倍率等比处理；默认视图负责全局趋势，节点密集时只抽稀圆点与表情，保留下来的表情必须具有可识别尺寸。逐级放大负责局部阅读，“最小”始终直接返回全局视图，“最大”倍率由节点数、当前画布和日期最小间距共同计算，必须让每个已记录日期都能显示；最小倍率的 SVG 基准宽度跟随阅读画布，固定纵轴栏和首节点安全区分别计算，不能因宽屏拉伸而把左侧留白同步放大，也不能以固定倍率冒充最大细节。
15. 手机倒计时、进度目标、空间与周卡使用同一套横向吸附规则：卡片停稳后，距离视口中心最近的一张自动成为当前选择；选中描边必须在滚动容器内预留完整空间。空间与周卡采用居中主卡加受控相邻卡露出的构图，首卡只露下一张、末卡只露上一张，滚动内容不得越过所属面板外框。倒计时日期独占提示行，表情、正文和剩余天数共享内容行的视觉中心。
16. 全新数据只预置一个“健康”空间，考研、工作及自定义空间由用户按需建立；示例备份和已有数据不因默认值变化而自动删除空间。
17. 日程的四种状态在编辑卡片、周报预览和下载图中保持同一语义：好好好使用贝拉番茄红、还不错使用嘉然贝壳粉、这期拉了使用旧版克制棕 `#89777F`、未设置使用乃琳深岩暗蓝灰。负面结果不直接绑定成员应援色。完成、调整、未完成三类任务结果分别使用独立音型，“记录今天”和“保存表情”共用第四种确认音；所有音量只做轻提示，不能遮盖系统或媒体声音。
18. 周报的任务汇总与日状态是两组不同语义：任务完成使用绿、任务调整使用黄、任务未完成使用红；每日总体状态遵循上一条的四种颜色。预览与横竖版下载图都从同一套调色板取值。
19. 每张曲线卡以第一指标颜色作为组件主色；新增节点使用实色主按钮，下载、菜单、最小、缩放和最大使用同色系浅层级，不能混入固定的紫色或乃琳色。危险操作仍保留危险色。
20. 数据操作使用固定风险语义：备份使用乃琳深岩暗蓝灰实色主按钮，恢复使用柔和紫色次按钮，安装使用薄荷绿，清空记录使用柔和危险红；桌面顶栏、手机顶栏和个人页数据保险箱保持一致。

## 视觉验收矩阵

每次影响布局的修改至少检查以下六档：`390px` 手机、`768px` 平板、`1024px` 紧凑桌面、`1440px` 宽屏、`1920px` 大桌面和 `2560px` 超宽屏。验收不只看“有没有溢出”，还要逐项确认：

1. 角色、文字、菜单、图表节点之间没有非设计性的遮挡。
2. 标题和正文没有因列宽过窄产生难看的逐字换行。
3. 图像与对应文案在视觉中心或基线上对齐。
4. 表单没有暴露浏览器默认样式，按钮的点击区域在触屏上足够稳定。
5. 空状态、短内容和长内容都能保持合理密度，宽屏不出现失控的空洞。
6. 图表缩放、节点选择和多指标仍完整可用；视觉抽稀不得修改数据本身。
7. 页面没有横向撑破视口，固定导航、弹窗和展开菜单不会互相覆盖。
8. 手机曲线节点过密时只抽稀贴纸和圆点装饰，曲线、数据、命中区域和节点详情必须全部保留；用户逐级放大时应恢复更多节点装饰，到动态“最大”级时每个已记录日期都必须可读。
9. 导出画布的高度应由实际内容决定，页脚紧随内容收口，不用固定空白维持某个比例。

`css/design-system.css` 中的“兼容别名”供旧代码过渡使用。新代码应优先使用 `--color-*`、`--member-*`、`--space-*`、`--radius-*` 和 `--shadow-*` 命名。
